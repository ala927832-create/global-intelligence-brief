# GIB V2｜內容缺漏與深讀可見性修補：完成紀錄、批判性驗收（2026-10-28）

## 1. 結果判定

**結論：此次修補通過「不空白、有來源重點、深讀專題能實際開啟」的工程／內容可讀性測試；距離契約 V2 要求的 30–40 分鐘 Essential、40–50 分鐘 Deep Research，以及 P2 正式編輯查核仍有明顯落差。P2 = HOLD；P3 正式真機試刊未獲准；正式發刊 OFF。**

這次不把網頁產生、CI 綠燈、兩篇歷史專題或九則新聞來源索引直接等同於合格的當日全球新聞出版品。

## 2. 已經真正改好的地方

1. `gib/publish_v16.py`：原本一遇到缺少 Gemini 編輯稿就顯示「缺少完整研究證據」的占位文字，改為 `source_grounded_digest` / `source_grounded_fallback`。它只能使用該事件既有的來源摘要，或帶有**真實匹配 source_id** 的 `reported_key_points` / `source_digest.points`；無法支持的內容不會編造。如果來源只有標題，會直接說明沒有足夠資訊，並提供原文連結，而不是冒充完整的重點整理。
2. 深度閱讀：即使 Gemini 沒有研究稿，也會提供明確標示為「來源導讀、非深度研究」的實際閱讀內容，避免空白；有研究稿時則加上直接跳轉、可定位的研究章節、問題、結論及可推翻條件。
3. 契約 V2 讀時以 `config/frozen_contract.json` 為準。原先硬編碼的 10–15 / 30–45 分鐘標籤已由正式契約讀取；內容不足時仍標成 QA 未驗收。
4. 正式研究篇數檢查同步改為 **至少 1 篇符合證據標準的研究（容許 1–2 篇）**，而非要求兩篇才能通過。原有一手證據比對、Gemini 實質改稿、人工作業及發布鎖仍然保留。
5. `docs/qa-web-v2/essential.html`、`deep.html`：相同來源清單，提供 **9 則 2026-10-28 真實新聞的可見重點摘要**（每則主文 + 至少 3 條具體重點 + 查核限制 + 原始連結）。深入專題兩篇可從頁首明顯入口進入；資料期間分別標示 IMF 10/13 與 BLS 10/14 / Fed 9/16，沒有假裝兩篇是 10/28 新發生事件。
6. 同步建立 `docs/qa-web-v2/source_grounded_20261028.json` 作為可審核的來源資料（9 則、15 個來源連結），避免網頁與資訊版本失去對照。

### 不能再發生的問題

1. **不能把「來源索引已讀取」當成「新聞全文已讀取」**。來源只有 snippet 時，就必須明確標成索引級報導；要形成完整新聞重點需取得來源實際正文或官方證據內容。
2. **不能把無證據、無研究稿的 Deep 章節假裝已完成**。新版已有可讀內容的降級方式，但正式深讀仍需專題實質原始材料。
3. **不能為達 40–50 分鐘而重複相同文字**。目前實際讀時不足，公開承認；增加字數必須先增加可驗證新聞材料與研究實質內容。
4. **不能把歷史研究視為當日新新聞**。Deep 兩篇已標原始發布時間；正式晨報應製作與當日最重要新聞有關的研究，引用跨期資料時分清日期。
5. **不能再用「測試綠燈」代替 P2 編輯簽核**。未完成的 P2 主張驗證、原始文章正文與 Gemini 二輪實質編輯，仍列為 HOLD。

## 5. 未來進入 P2 正式驗收前的必要工作（不視為已完成）

- 實際來源取得：加入合法可得的原始新聞全文或官方文件正文，抽取 source-id 綁定的逐項重點；付費牆、robots 限制及無法取得全文的報導需保留不完整註記，不能繞過。
- 先採集已核准的六次真實截稿時段證據，再回推頭條優先級、跨媒體獨立交叉比對、晨晚差異。
- 將 Deep 實質研究改以當日頭條重大議題為對象，聚焦 1–2 篇，而不是只延用舊研究；維持官方原始資料、歷史脈絡、反方論證及失效條件。
- Gemini 二輪編輯要有可比對前後差異、逐項數字／日期／引文查核結果，以及人工編輯最終簽核。
- 重做 V2 30–40 / 40–50 分鐘**真人閱讀量測**並確認內容密度，不以文字堆積達標。
- P2 真正完成才決定正式 P3 / P4 工作範圍與發行。
