# 正式上線不得跳過的關卡

此檔案是操作驗收規則，**不是目前已通過的證明**。

## 10 個交易日的來源品質

- 在**新的、獨立** `global-intelligence-brief` Repository，先上傳完整專案。
- 先設定 `FREENEWS_API_KEY` 及 `GEMINI_API_KEY` 為 GitHub Secrets，完成 Google AI Studio 免費層確認。**不要在聊天、程式碼或公開 Issue 貼上金鑰**。
- 設 Repository variable `GEMINI_FREE_TIER_CONFIRMED=1`（僅在確實免費且未連結付費層的專案中）。
- 設 `QA_ARMED=1` 後可執行排程 QA；永不自動啟用 Pages、LINE、正式發布。
- 每個符合市場交易日的日期要有晨報與晚報兩條**真實來源**紀錄；週末與指定休市日不計入。
- 每期至少檢查 8–12 則新鮮新聞、官方事件時間、事件聚類、同源去重、來源多樣性、至少 3 個已人工核對的重要 claim，以及 2–3 篇真正經過額外證據核對的深度專題。
- 晚報應比對**當天早報快照**，不能直接引用 17:30 同步啟動、尚未完成的 Zinc 警示。
- 只靠模型「修訂成功」與新聞摘要，**不代表每個主張為真**。
- **每次 CI 只產生 QA Artifact 和記錄**；若內容或額度不足，記錄失敗而非補寫新聞。

## EPUBCheck（每份正式候選 EPUB）

用官方開源 EPUBCheck 5.4.0 或更新維護版逐一驗證：早報速讀、早報深讀、晚報速讀、晚報深讀。**ZIP/XHTML 格式自行測試不是 EPUBCheck。**

CI 正式檢查安裝檔由 W3C 專案發佈頁取得；沒有工具就 fail，不得宣稱通過。

## BOOX Note Air4 C＋NeoReader 的真人實測

每個版本至少測：字體一般／放大、行距、章節目錄、跳回來源、含表格／圖表長篇、黑白／彩色對比、避免圖表裁切與卡片擠壓、是否有大型留白。把實際閱讀器截圖、測試日期及結果保存於 `qa_data/device`，不以概念圖代替。
